# Отчёт: проверка прав преподавателя

## Цель

Проверить, что пользователь с ролью `teacher` имеет доступ только к группам, назначенным ему администратором, и не может выполнять административные действия.

## Проверенная по исходному коду модель доступа

В приложении используются роли `student`, `starosta`, `teacher` и `admin`. Назначения сотрудников на группы хранятся в таблице `staff_groups`.

Основные правила реализованы в `backend/app/access.py`:

- список разрешённых групп определяется через назначения сотрудника;
- запросы к группам ограничиваются назначенными группами;
- при попытке обратиться к чужой группе возвращается HTTP 403;
- изменение данных студентом запрещено;
- административные операции доступны только роли `admin`.

## Матрица ожидаемого поведения

| Операция | Ожидаемый результат для преподавателя |
|---|---|
| Просмотр списка групп | Только назначенные группы |
| Просмотр своей группы | Разрешено |
| Просмотр чужой группы | HTTP 403 |
| Просмотр студентов своей группы | Разрешено |
| Просмотр студентов чужой группы | HTTP 403 |
| Просмотр занятий своей группы | Разрешено |
| Просмотр статистики своей группы | Разрешено |
| Изменение посещаемости своей группы | Разрешено |
| Изменение посещаемости чужой группы | HTTP 403 |
| Создание группы | HTTP 403 |
| Создание сотрудника | HTTP 403 |
| Создание предмета | HTTP 403 |

## Автоматизированные проверки

Файл `backend/tests/test_teacher_permissions.py` содержит интеграционные тесты FastAPI. Они создают тестового преподавателя через административный API, назначают ему одну из демонстрационных групп и проверяют разрешённые и запрещённые запросы.

## Замечания по реализации

1. В текущей реализации роли `teacher` и `starosta` имеют одинаковые права на изменение данных в назначенных группах. Если по требованиям проекта староста должен иметь более ограниченные права, это следует изменить отдельно.
2. Проверка тестового API использует SQLite в памяти. Это изолирует тесты от рабочих данных, но не заменяет проверку соединения и поведения PostgreSQL в запущенном окружении.
3. Эндпоинт `/health/db` не требует авторизации и возвращает количество записей в таблицах. Для публичного production-сервера рекомендуется ограничить доступ к нему.

## Статус

Это отчёт по анализу исходного кода и подготовленным автоматизированным тестам. Фактический результат выполнения тестов и проверка живого экземпляра PostgreSQL должны быть заполнены после запуска команд из `testing/README.md`. Не отмечайте проверки как пройденные до получения реального результата.
