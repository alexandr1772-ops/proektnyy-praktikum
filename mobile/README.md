# Мобильный клиент трекера посещаемости

Android-приложение на Kotlin и Jetpack Compose. Для локальной разработки достаточно Android Studio, Android SDK 35 и JDK 17 или совместимого JDK из Android Studio. Откройте папку `mobile` и запустите конфигурацию `app`. Минимальная версия устройства — Android 8.0 (API 26). При запуске Gradle из терминала на macOS можно выбрать JDK из Android Studio через `export JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home"`.

## Демо без сервера

По умолчанию приложение использует локальный журнал. Стартовые данные включают две группы, несколько студентов и занятий. Изменения сохраняются на устройстве между запусками. Для повторного демо можно создать новую группу и занятие. Чтобы начать со стартовых данных, очистите данные приложения на тестовом эмуляторе.

| Логин | Пароль | Доступ в демо |
| --- | --- | --- |
| `admin` | `1234` | Все группы, студенты, предметы и занятия |
| `teacher` | `1234` | Журнал, статистика, студенты и занятия группы ИС-21 |
| `student` | `1234` | Собственная статистика и профиль |

1. Войдите как `admin`. Откройте **Данные → Группы → Добавить**. Создайте группу. При необходимости добавьте предмет в разделе **Предметы**.
2. Через меню в разделе **Данные** выберите **Студенты**, укажите новую группу и добавьте двух студентов вручную или импортируйте CSV. В разделе **Занятия** этой же вкладки добавьте занятие.
3. Перейдите на нижнюю вкладку **Занятия**, откройте созданную пару и нажмите **Отметить всех → Сохранить всю группу**. Для изменения отдельной отметки выберите статус на карточке студента, при желании заполните примечание и нажмите **Сохранить отметку**. Повторная массовая отправка для уже отмеченного занятия отклоняется. Удаление занятия с отметками тоже отклоняется.
4. В **Статистике** проверьте пересчёт по группе, студенту и предмету. Выберите **Весь период**, если занятие было до начала текущего периода. На вкладке **Риск** можно посмотреть локальную оценку по отметкам. В режиме API эта вкладка показывает прогноз сервера.
5. Для экспорта выберите группу и **Данные → Студенты → Экспорт CSV**. Войдите как студент и проверьте, что доступны только его статистика и профиль.

Для импорта подходит UTF-8 CSV с заголовком `full_name` (также принимаются `name` и `ФИО`). Разделитель — запятая или точка с запятой. В примере ниже две записи.

```csv
full_name
Иванов Алексей Олегович
Петрова Мария Игоревна
```

В локальной статистике `present` и `late` считаются посещением. `absent` входит только в знаменатель. `excused` исключается из расчёта. Используются сохранённые отметки за выбранный период. При пустом знаменателе интерфейс показывает отсутствие данных. Согласуйте это правило с бэкендером. Если API будет отдавать готовую статистику, подключите её вместо расчёта по журналу.

## Подключение API напарника

Экраны работают через `AttendanceRepository`. Локальный источник находится в `LocalAttendanceRepository.kt`, запросы — в `ApiAttendanceRepository.kt`, разбор ответов — в `JournalJson.kt`.

1. Сверьте черновой контракт ниже с фактическим OpenAPI/Swagger бэкенда. Обновите пути, поля, формат входа и преобразования в сетевом адаптере. Если сервер отдаёт справочники и журнал отдельными запросами, соберите их в `load()` адаптера. Проверьте, что ограничения доступа соблюдает сервер.
2. После запуска бэкенда выполните команду из папки `mobile`.

   ```bash
   ./gradlew :app:assembleDebug -PattendanceSource=api -PattendanceApiUrl=http://10.0.2.2:8000
   ```

   `10.0.2.2` подходит для Android Emulator, когда сервер запущен на компьютере. Для телефона укажите IP компьютера в общей локальной сети. Сервер должен слушать доступный телефону интерфейс. HTTP разрешён в отладочной сборке, для релизной сборки используйте HTTPS.

3. Установите `app/build/outputs/apk/debug/app-debug.apk` и войдите с учёткой сервера. Повторите сценарий демо и проверьте ответы на дубль отметки, попытку удаления занятия с отметками и запрос чужих данных. Для возврата в демо пересоберите приложение с `-PattendanceSource=demo`. При обновлении APK демо-данные сохраняются только на устройстве.

Для Android Studio можно задать те же свойства в локальной пользовательской конфигурации Gradle (`attendanceSource=api` и `attendanceApiUrl=...`) и пересобрать `app`.

### Черновой контракт сетевого адаптера

| Операция | Метод и путь | Формат |
| --- | --- | --- |
| Вход | `POST /auth/login` | JSON `login, password` → `access_token, user`. У `user` есть `login, role`, для преподавателя `group_ids`, для студента `student_id`. Роли — `admin, teacher, student`. |
| Чтение журнала | `GET /journal` | JSON со списками `groups, students, subjects, lessons, attendance` и опциональным `predictions`. Остальные запросы используют заголовок `Authorization: Bearer …`. |
| CRUD | `POST /{entity}`, `PUT /{entity}/{id}`, `DELETE /{entity}/{id}` | `entity` — `groups, students, subjects, lessons`. |
| Отметить группу | `POST /lessons/{id}/attendance/bulk` | Один JSON-запрос `{"marks":[...]}`. |
| Добавить или изменить отдельную отметку | `PUT /lessons/{id}/attendance/{studentId}` | Одна отметка в JSON. |
| Импорт студентов | `POST /groups/{id}/students/import` | JSON `{"csv":"…"}`. Ответ может содержать `message`. |
| Экспорт отчёта | `GET /groups/{id}/attendance.csv` | Тело ответа — CSV в UTF-8. |

В журнале группа имеет `id, name`. Студент — `id, full_name, group_id`. Предмет — `id, name` и опциональный `kind`. Занятие — `id, group_id, subject_id, date, start, end, pair`, где дата — `YYYY-MM-DD`, время — `HH:mm`. Отметка в журнале — `lesson_id, student_id, status, note`. При записи `lesson_id` уже передаётся в URL. Статусы — `present, absent, late, excused`. У прогноза есть `student_id, risk` (`low, medium, high`) и опциональный `note`.

## Проверки

```bash
./gradlew :app:assembleDebug :app:testDebugUnitTest :app:lintDebug
```

Тесты проверяют локальный сценарий журнала, области доступа, CSV, статистику, защиту от дублей и HTTP-запросы к локальной имитации API. Сценарий выше подходит для ручной проверки интерфейса.
