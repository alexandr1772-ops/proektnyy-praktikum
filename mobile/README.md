# Mobile client / Мобильный клиент

Нативное Android-приложение для отметки посещаемости занятий. Приложение является клиентом REST API бэкенда на Python (FastAPI) и не хранит данные само.

**Ответственный:** Климов Н.

**Статус:** разработка начата. Платформа выбрана, подготовлены 5 макетов экранов Android-приложения. Рабочая версия приложения находится в разработке.

## Платформа и стек

- Язык: **Kotlin**.
- Интерфейс: **Jetpack Compose**.
- Среда разработки и сборки: **Android Studio**.
- Сеть: HTTP-клиент (Retrofit или Ktor) для запросов к REST API.

### Почему нативный Android

- Разработчик знает Kotlin, поэтому не тратится время на изучение нового фреймворка.
- Приложение удобно проверять на реальном Android-телефоне.
- Jetpack Compose упрощает создание экранов со списками и формами отметки.

Ограничение: приложение работает только на Android. На iPhone его не запустить.

## Экраны

1. **Вход / выбор роли.**
2. **Список занятий:** предмет, группа, дата, пара.
3. **Отметка посещаемости:** список студентов, статус для каждого: `present`, `absent`, `late`, `excused`.
4. **Статистика:** процент посещаемости по группе и по студенту.
5. **Группа риска:** студенты с низкой или резко упавшей посещаемостью (зависит от ML-функции на стороне бэкенда).

Макеты экранов добавлены в папку `mobile/mockups/`.

## Работа с API

Приложение обращается к бэкенду по адресу `http://<IP-ноутбука>:8000`.

| Где запущено приложение | Адрес API |
| --- | --- |
| Реальный телефон в одной Wi-Fi сети с ноутбуком | `http://<IP-ноутбука>:8000` |
| Эмулятор Android Studio | `http://10.0.2.2:8000` |

Уже доступные эндпоинты бэкенда:

- `GET /health`
- `POST /students`, `GET /students`
- `POST /lessons`, `GET /lessons`
- `POST /attendance`, `GET /attendance`

Список будет расширяться вместе со схемой БД.

### Что нужно настроить для работы с телефона

- В `compose.yaml` порт опубликован как `127.0.0.1:8000:8000`, из-за этого телефон не достучится до API. Для демо нужно заменить его на `8000:8000` (согласовать с Гусаровым А.).
- Брандмауэр ноутбука не должен блокировать порт 8000.
- В отладочной сборке Android нужно разрешить обычный HTTP (`usesCleartextTraffic`).
- Если Wi-Fi университета изолирует устройства друг от друга, использовать точку доступа на телефоне.

## Сборка

1. Открыть папку проекта в Android Studio.
2. Дождаться синхронизации Gradle.
3. Для установки на телефон: **Build → Build Bundle(s) / APK(s) → Build APK(s)**, затем передать APK на телефон и установить.
4. Для запуска из Android Studio: подключить телефон по USB с включённой отладкой и нажать **Run**.

## Показ на демо

- **Вариант A (основной):** живой Android-телефон и ноутбук в одной Wi-Fi сети. На ноутбуке запущен `docker compose up --build`.
- **Вариант B (запасной):** видеозапись экрана телефона на 1-2 минуты, файл хранится в `demo/`. Записывается заранее на случай, если на паре не будет сети.

На демо нужно показать: реальную отметку посещаемости, пересчёт статистики и экран риска.
