# Проектный практикум — трекер посещаемости

Учебный групповой проект для учёта посещаемости занятий: REST API на FastAPI, PostgreSQL и мобильный Android-клиент. Backend и база запускаются одной командой через Docker Compose; таблицы и демонстрационные данные создаются автоматически.

## Запуск одной командой

Нужен Docker Desktop или Docker Engine с Compose v2. Из корня репозитория:

```bash
docker compose up --build
```

После запуска доступны:

- `http://localhost:8000/health` — состояние API;
- `http://localhost:8000/health/db` — соединение с PostgreSQL и количество записей;
- `http://localhost:8000/docs` — Swagger UI;
- `/groups`, `/lessons`, `/attendance`, `/stats`, `/risk` — рабочие эндпоинты проекта.

`GET /health/db` подтверждает соединение и возвращает счётчики шести основных таблиц: `users`, `groups`, `students`, `subjects`, `lessons`, `attendance`.

Остановка без удаления данных:

```bash
docker compose down
```

Полностью чистый повторный запуск:

```bash
docker compose down --volumes
docker compose up --build
```

## Переменные окружения и секреты

В репозитории хранится только [.env.example](.env.example). Файл `.env` исключён через `.gitignore` и не должен попадать в GitHub. Для собственных значений создайте локальный `.env`:

```dotenv
POSTGRES_DB=attendance
POSTGRES_USER=attendance
POSTGRES_PASSWORD=your_local_password
ADMIN_LOGIN=admin
ADMIN_PASSWORD=your_local_admin_password
```

Compose автоматически читает `.env`. Без него используются только локальные демонстрационные значения, поэтому проверочный запуск не требует ручных правок.

## Доступ к API с телефона

Порт опубликован в `compose.yaml` как `8000:8000`, без привязки к `127.0.0.1`. Телефон и ноутбук должны находиться в одной Wi-Fi сети.

1. Узнайте локальный IPv4-адрес ноутбука (`ipconfig`, `ip addr` или `ifconfig`).
2. Разрешите входящие TCP-подключения к порту 8000 в брандмауэре.
3. На телефоне откройте `http://<IP-НОУТБУКА>:8000/health`.

Например: `http://192.168.1.25:8000/health`. Для Android-клиента с обычным HTTP в отладочной конфигурации должен быть разрешён cleartext-трафик.

## База данных и ER-диаграмма

[ER-диаграмма и ограничения схемы](docs/er-diagram.md) · [Диаграмма PNG](docs/er_diagram.png) · [Схема DBML](docs/schema.dbml).

База хранит пользователей, группы, студентов, предметы, занятия и отметки. Таблицы `staff_groups` и `access_sessions` хранят назначения сотрудников и сессии API. При первом запуске создаются администратор, две группы, 15 студентов, пять предметов, занятия и отметки за последние недели. При работе с существующей базой приложение добавляет поля `students.user_id` и `attendance.note`, а также недостающие таблицы.

## API спринта 2

Вызовите `POST /auth/login` с логином и паролем. Для следующих запросов передавайте `Authorization: Bearer <access_token>`. В Swagger UI нажмите **Authorize** и вставьте значение `access_token` из ответа. Токен действует восемь часов. Его нужно передавать и из Android-клиента.

| Метод | Путь | Назначение |
| --- | --- | --- |
| `GET`, `POST` | `/groups`, `/students`, `/subjects`, `/lessons` | Списки и создание записей |
| `GET`, `PUT`, `DELETE` | `/groups/{id}`, `/students/{id}`, `/subjects/{id}`, `/lessons/{id}` | Просмотр, обновление и удаление. Для занятия с отметками удаление возвращает 409 |
| `POST` | `/staff` | Создать аккаунт преподавателя или старосты с назначением групп |
| `PUT` | `/students/{id}/account` | Создать аккаунт существующему студенту. Администратор также может передать `account` при создании студента |
| `GET` | `/groups/{id}/students`, `/lessons/{id}/attendance` | Список студентов группы или отметок занятия |
| `POST`, `PATCH` | `/attendance`, `/attendance/{id}` | Создать или исправить отметку. Поле `note` принимает текст или `null` |
| `POST` | `/lessons/{id}/attendance/batch` | Одним запросом отметить всю группу. По умолчанию `present`, исключения передаются в `overrides` |
| `GET` | `/stats?group_id={id}`, `/stats/students/{id}`, `/stats/groups/{id}`, `/stats/subjects/{id}` | Статистика по списку студентов, студенту, группе или предмету |
| `POST`, `GET` | `/groups/{id}/students/import`, `/groups/{id}/attendance.csv` | Импорт списка и экспорт журнала CSV |
| `GET` | `/risk?group_id={id}&student_id={id}` | Оценка риска. Параметр `student_id` можно опустить для всей группы |

**Правило статистики.** Процент = `(present + late) ÷ (present + absent + late + excused) × 100`. Опоздание засчитывается как присутствие. Уважительный пропуск входит в число отмеченных занятий. Занятия без отметки не входят в расчёт. При отсутствии отметок возвращается `0.0`. Для группы и предмета процент считается по общим счётчикам отметок. Параметр `weeks` задаёт период от 1 до 52 недель, по умолчанию 8.

**Права.** Администратор работает со всеми данными. Преподаватель и староста работают с назначенными группами. Студент видит свой профиль, отметки, статистику и прогноз. Справочник предметов доступен после входа. Группы, предметы и аккаунты создаёт администратор.

**CSV.** Импорт принимает тело запроса в UTF-8 с типом `text/csv`. Первая строка — `full_name`, далее по одному имени на строку. Совпадения имён в файле или с карточками группы возвращают 409. При ошибке весь импорт откатывается. Экспорт содержит даты, пары, предметы, студентов, статусы и примечания.

## Тестирование и CI

```bash
cd backend
python -m pip install -r requirements-dev.txt
python -m pytest -q --cov=app --cov-report=term-missing --cov-fail-under=40
```

GitHub Actions выполняет pytest, проверяет Compose, собирает контейнеры, запускает FastAPI с PostgreSQL и проверяет заполнение БД через `/health/db`.

## ML-функция

`/risk` использует логистическую регрессию. На синтетической контрольной выборке получены **accuracy 0,76** и **F1 0,6066**. [Признаки, целевая переменная и воспроизведение метрик](docs/ml_plan.md).
